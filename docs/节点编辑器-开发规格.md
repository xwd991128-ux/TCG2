# 节点编辑器 开发规格（运行时 · 玩家自制卡）

> 用途：给开发 agent 直接照做的节点编辑器规格。核心 = **两线制（动作线/取值线）+ 节点内部布局 + 收起/删除行为 + 数值输入取值机制**。
> 前置上下文：`产品方案.md 7.6/7.6.1`、`阶段2-节点系统全集清单.md`（319 节点）、`阶段2-节点全量映射表.md`。
> 数据层已在 `Assets/TcgEngine/Scripts/Graph/GraphData.cs` 落地，本规格是 UI/交互层 + 运行判断的明确标准。

---

## 1. 页面布局（老板已拍板）

- **左 3/4**：节点画布（主战场）。
- **右 1/4 分上下两半**：
  - **上半 · 卡牌属性/参数面板**：选中卡牌时编辑卡面（费用/攻/血/描述）；**选中节点时编辑该节点参数**。节点上不铺满输入框，细节都进这里。
  - **下半 · 节点列表**：搜索 + 分类（对应 卡牌/触发/效果/行动/集合 分类）+ 最近使用 + 收藏。

---

## 2. 两线制：动作线 vs 取值线（核心分水岭）

节点系统必须区分两类连线，二者缺一不可：

| 类别 | 管什么 | 连的端口 | 视觉 | 例 |
|---|---|---|---|---|
| **动作线（执行流）** | 先做什么、后做什么的**顺序** | `执行`端口 ↔ `执行`端口 | **实线 + 箭头** | `打出时 → 随机取2 → 抽目标` |
| **取值线（数据流）** | 把一个**值**喂给参数（动态取值） | 数据端口 ↔ 同类型数据端口 | **虚线 + 按类型配色** | `目标攻击力(整数) → 伤害量` |

- `GraphData.cs` 里 `NodePortType`（`Exec / Bool / Int / String / Card`）已区分 `Exec` 与数据端口，接线合法性据此判断：
  - **Exec 端口只能连 Exec 端口**；数据端口只能连 **同类型** 数据端口。
- 若混淆（只有动作线）→ 无法动态取值；只有取值线 → 无法表达执行顺序。两者必须同时存在且视觉/数据结构能区分。

## 3. 节点内部布局（尺寸定死，可直接写 UI 自动布局）

一个节点 = 头部一行 + 若干"配对端口行" + 底部说明区。

### 垂直方向（从上往下）
1. **头部 Header · 高 32px**
   - 最左 **6px 分类色条**（贯穿整卡，标识分类）。
   - 标题文字：字号 14，左 padding 12。
   - 右上角两个按钮：**收起「一」** 与 **删除「×」**，各 16×16、间距 4（见第 4 节）。
   - 下方 1px 分割线。
2. **端口行（核心）· 每行高 28px（触屏建议 32）**
   - **输入口贴左缘、输出口贴右缘，共用同一水平中线** → 连线天然水平、画布整洁。
   - 行数 = `max(输入个数, 输出个数)`（某行只有输入没输出也允许）。
   - 端口锚点坐标：
     ```
     y_i = headerBottom + i * 28 + 14      // +14 = 半行高，得到行中点
     输入口圆心 = (nodeLeft + 6,        y_i)
     输出口圆心 = (nodeRight - 6,       y_i)
     ```
3. **底部说明/参数区 · 可折叠**：一句人话（如"对目标造成 X 点伤害"）≤2 行；无则高度 0。

### 水平方向
- 节点宽 **min160 / max320**，按最宽一行文字自适应（左右各 +12 padding）。
- 端口 = **彩点（直径 10）** + 标签；左输入 `点→标签`，右输出 `标签对齐→点`。

### 端口彩点配色（决定"能不能连"，防呆核心）
| 彩点 | 类型 |
|---|---|
| 🔵 蓝 | 整数 |
| 🔴 红 | 卡牌 |
| 🟢 绿 | 集合 |
| ⚪ 灰 | 布尔 / 玩家 |

**规则：只有同色（或允许转换）端口才能相连**。开始拖某输出口时，仅匹配的输入口变亮，其余全灰——连不上的不用试。

## 4. 右上角两个按钮（收起 / 删除）

### 「一」收起 = 节点还在，只是缩起来（线不消失）
- 收起后节点缩成一行头（高约 32px），**端口缩成左右各一个迷你锚点**：
  - 所有输入线 **汇入左侧一个迷你输入点**；所有输出线从**右侧一个迷你输出点**散出。
  - **连线不断、逻辑照跑**，只是线"贴"到收窄节点左口/右口。
- **角标计数**：收起节点上方给个圆徽（如 `×2`），表示连进来几条线，防止被误判为孤立。
- **悬停细目**：收起时看不见具体端口名，悬停弹出：
  > 「入 2 条 · 出 1 条：来自【取牌库】、连向【抽目标】」
- 再点「一」展开 → 迷你点重新展开成具体端口，线自动散回各自端口。

> 反面典型：若收起真的把线删了 → 玩家看不懂这节点连着谁，必须避免。

### 「×」删除 = 节点 + 它身上的全部连线一起删
- 属不可逆真删，**必须支持撤销（Ctrl+Z）**或删除前轻确认，防手滑毁整条效果。

## 5. 数值输入口的取值机制（"X 在哪配置"）

任何数值参数（伤害/数量/加攻……）都是节点的一个**数据输入口**，取值方式二选一：

**方式一：手填固定值（默认）**
- 节点上显示可点的数值框，如 `X = 5`。
- 点它 → 右侧"参数面板"弹出数字输入框修改。
- 用于固定数值：造成 5 点伤害 / 抽 2 张牌。

**方式二：接取值线，自动取上游值（动态）**
- 从上游节点（如"目标攻击力"）拖取值线连到这个输入口。
- 连上后该框变成 `← 目标攻击力`，**不再手填，运行时用上游算出的值**。
- 用于动态：造成 = 目标攻击力 点伤害 / 抽 = 攻击力 张牌。

**覆盖关系（关键）**：一个输入口**永远保留手填默认值做底**；只有接取值线时自动值覆盖它，**线一拔即回落默认值**。端口不会因拔线而空、效果不会崩。

**数据落地（已支持）**：`GraphNodeInput { name, type, intValue/boolValue/stringValue }` 即"默认固定值"；运行时判断：
```
来源连线 != null ? 用上游的值 : 用该输入端口的默认值
```
（与 `NodeGraphRunner.GetInput` 现行逻辑一致：先查连线，无则用节点固定输入值。）

**给玩家的一句话提示（放编辑器）**："输入框填的数叫『固定值』；把一个节点连到这个框上，就改用那个节点算出的值。"

## 6. 可发现性与反馈（决定"符不符合使用习惯"）

1. **空画布引导**：首次无节点时，画布中央放半透明提示"从右边选一个节点拖到这儿开始"。
2. **连线合法性高亮**：拖口时仅匹配目标口变亮，其余变灰。
3. **端口按类型分色**（第 3 节配色表），非按花哨分色。
4. **节点按分类配色 + 图标**：找节点靠"颜色+图标"扫，比读字快。
5. **最小可用效果引导**：新手引导搭一个极简效果（如"打出时：造成 1 点伤害"），建立成就感、最留人。
6. **缺输入报错**：必填口未接 → 端口/节点外圈变红 + 感叹号，悬停显示"还差『目标』"；保存前拦截、试跑时醒目提示。
7. **环形检测**：禁止连成环（或明确提示），避免死锁。
8. **运行回放（调试）**：游戏内试跑时高亮当前执行的线/节点，玩家看到"我的效果怎么跑的"。
9. **即时预览**：改一个数字，卡面文本/说明实时更新。

---

## 7. 构建次序（别贪多，先做能用的）

- **Tier1 MVP**：加节点 → 拖动 → 连线（两线制）→ 跑一个最简效果 → **保存/读取 `.diycard`**。先不做光影动画。
- **Tier2**：撤销/重做、复制粘贴、非法连线提示、收藏/最近。
- **Tier3**：运行高亮走线、节点折叠/最小化、搜索优化、主题皮肤。

> 提醒：**保存/读取与 UI 同期做**，别等 UI 全做完再接数据——`GraphData`/`NodeGraphRunner` 与 UI 解耦，这一步会很顺。

| 项目 | 借鉴点 | 别照抄 |
|---|---|---|
| **Braverse**（卡牌+xNode技能图） | 触发按 `ActionType`（OnPlay/OnAttack…）分槽、节点基类 `Execute(上下文)→找下一节点`、结果统一装入一个 ActionResult、服务器跑效果+客户端只播画面 | 它是固定串行链，无自由分支、无四则/取余节点；条件节点为硬编码字段，扩展性差 |

| **Card-game-demo** | 成熟卡牌效果 Action 系统（Pre/Perform/Post） | 非节点编辑器 |
| **Irfish/node-graph** | Tick 驱动的逻辑流、中文注释 | 通用图，非卡牌场景 |
