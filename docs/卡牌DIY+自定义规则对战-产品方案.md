## 0. 产品一句话

一款让玩家**用可视化节点图自制卡牌与规则、并能对战**的卡牌游戏，定位 **创作者 / UGC 向**。

***

## 1. 核心需求（老板已逐项确认）

| 维度       | 决策                                        |
| -------- | ----------------------------------------- |
| 平台       | 先 PC，后移动                                  |
| 卡牌自定义    | 节点图（方案 A：首批 14 个官方节点）                     |
| 规则自定义    | 先白名单配置项，不改引擎；后期逐步开放                       |

| 开发节奏     | 阶段1 = 编辑器 Demo 验证                         |

### 关键约束（避免天坑）

* 不搞"完全开放引擎"：规则 = 官方白名单配置，引擎逻辑仅官方层开放（插件化规则集）。

* DIY 只进私房 + 信任本地文件 → 规避了 UGC 天梯平衡 / 服务器权威重建 / 大规模审核三大重负担。

## 3. 阶段1 Demo — 定稿规格（老板已确认）

### 3.1 目标（一句话）

> **验证"玩家用节点图做一张卡 → 能在本地人 vs AI 对局里真正打出来"这个核心闭环。**

### 3.2 范围边界（严禁超出）

| 做                           | 不做               |
| --------------------------- | ---------------- |
| 节点图编辑器（拖/连/存）               | 注册登录、账号存盘        |
| .diycard 导出/导入              | 社区上传、审核          |
| 人 vs AI 单机对局（沿用 Offline 模式） | 双人同机（已砍）、私房联机、天梯 |
| 把 DIY 图解释执行                 | 移动端、赛事、观战        |

### 3.3 功能清单（最小可用集 MVP）

1. **编辑器**

   * 左侧节点面板：14 个节点，按 4 类分组

   * 画布：拖入节点、连线（执行流=实线 / 数据流=虚线）、删除

   * 节点输入框：填固定值 或 拖连线取值（复用已改造的 ValueSource 体系）

   * 右侧实时预览卡面（费用/攻血/效果文字）
2. **卡牌数据**：输出 .diycard JSON（schema 1.0，meta + graph）
3. **对局**：固定官方规则（30血 / 法力0-12每回合+1 / 起手5张每回合抽1 / 手牌上限15）+ 人 vs AI（AIPlayer，先随机后深度）+ 出牌/攻击 + 解释器跑自制效果
4. **解释器**：NodeGraphRunner，拓扑排序执行，桥接现有 EffectData（已支持 amount）

### 3.4 节点图数据格式（核心规约）

```
.diycard = { schema, meta{id,author,title,cost,attack,hp,type}, graph }
graph   = { nodes[], connections[] }
node    = { id, defineId, posX, posY, inputs{}}     ✓ 对齐 Classic.ddcp
connect = { sourceNodeId, sourcePort, destNodeId, destPort }  实线=exec / 虚线=data
```

* 端口两类：**执行流**(exec/enter) 与 **数据流**(数值/卡牌)

* 运行时 NodeGraphRunner 按 connections 拓扑排序，逐个节点 → 查 NodeDef 字典 → Handler → 内部复用现有 EffectData

### 3.5 最小节点清单（方案 A，14 个）

* 入口/目标：100001 效果入口、100002 取目标

* 动作：100010 造成伤害、100011 治疗、100012 抽牌、100013 加Buff、100014 召唤、100015 弃牌、100016 加法力

* 数据/运算：100020 取攻击力、100021 取血量、100022 取法力、100030 四则运算(Add/Sub/Mul/Div/Mod)

* 流程：100040 条件判断、100041 循环N次、100042 求和（预留）

> 足以组合出「战术洞察」：目标每1攻抽1张。（入口→取攻击力→四则运算→抽牌）

### 3.6 验收标准（Demo 完成定义）

1. 编辑器能拖 5 节点连出「战术洞察」效果图
2. 保存导出 .diycard，重新导入无损坏
3. 人 vs AI 对局出这张卡，效果正确生效（目标5攻 → 抽5张）
4. AI 正常对战、会打出/施放自制卡；普通官方卡不受影响

### 3.7 暂存默认项（无强度校验 / 预置官方卡 / 中文界面）

* ① 预置一批官方卡（便于组牌对战）

* ② DIY 暂不做强度校验（信任本地文件），正式版再加白名单

* ③ 编辑器界面用中文

### 7.2 规则系统：数值 + 回合流程 节点化编辑
- **数值规则**（沿用现有白名单思路，做成节点化修改，而非仅键值表）
  - 可改项：`starting_hp` / `mana_per_turn` / `mana_max` / `cards_start` / `cards_per_turn` / `cards_max` / `deck_size` / `dup_max` / `mulligan` / `second_bonus`
  - 每一项带：允许范围、默认值、校验规则（例如 `starting_hp ∈ [15, 60]`）
- **回合流程**（阶段2 新增开放层，引擎仍官方固定）
  - 可改项（节点化编排 "回合步骤序列"）：每回合抽牌数、能否额外移动/出法、先手后手权、超时秒数、回合内动作顺序
  - 示例：`RoundFlow = [Draw N from serialized deck] -> [Mana+1] -> [PlayerAction] -> [AI_Action]`
  - **守卫**：这些项仍基于官方提供的"回合步骤原子"，玩家只能**重排/增删"官方原子"**，不能发明全新引擎行为
- `.diyrule` 文件：`{ schema, meta{id,author,title}, rules[]，round_flow[] }`
- 平衡：每次改动即时做**系统建议**（强度/时长提示），阶段2 不强制拦截（信任本地），但记录为阶段3 审核输入

### 7.3 私房对战（成熟体验）
- **建房**：选规则(.diyrule/默认) → 提炼为**规则 hash** → 生成房号/share code → 发布到房间列表
- **加入**：房号直连 / 房间列表查找 / 分享码；标签展示（标题/规则说明/人数/房主）
- **房管理（完整）**：房主改房名/规则/开放门票、踢人、设为观战、只允许好友、中途暂停
- **断线/重连**：会话保留 N 秒，断线重连恢复对局；超时由房主或系统接管/判定
- **房内观战**：非玩家可旁观本房（阶段2 简化版，阶段4 做官方直播级观战）
- **房内聊天**：文字聊天、快捷表情、对局内表情
- **DIY 数据流**：双方本地持有 .diycard，仅同步"卡牌ID + 签名 + 规则 hash"；规则 hash 不一致则拒绝开战

### 7.4 账号与云存盘（真实账号）
- 注册/登录（用户名+密码 / 可选第三方）、账号服务端验证 Token
- **云存盘**：作品(.diycard/.diyrule)、战绩/积分、设置，多端同步(为阶段5移动端铺路)
- **战绩/积分**：记录 胜/负/场次/胜率/MMR雏形，私房与单人分别统计
- **个人主页/展示**：昵称、自定义头像/头像框、展示自制作品列表、公开战绩
- 作品归属：每个 .diycard/.diyrule 绑定 account_id；导出/导入保留作者信息

### 7.5 DIY 作品管理
- **作品/草稿/版本**：本地草稿箱、作品列表、重命名、版本迭代/回滚
- **分享/收藏**：导出分享码/文件、导入他人作品、收藏他人作品到本地
- **作品美化**：卡面封面图/边框/标签选择，美化展示页
- （创意工坊上传/评价/投票/评选 → 阶段3）

### 7.6 节点系统：对标醉梦全集（319 个，阶段2 全部完成）★核心主线

- **全集来源**：以导入的 `zmcs/NodeDoc.xml`（319 ActionComment 节点）为全集蓝本，按分类推进。
- **分类分布（来自 NodeDoc.xml 实测）**：卡牌/集合运算/玩家/Buff/牌堆/增益/行动/游戏/其他等（总 319）。
- **三档推进（Tier 分批，全部在阶段2 完成，只是先后次序）**
